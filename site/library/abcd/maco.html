01

First, picture the problem.

A reconfigurable array’s arithmetic units, connections, and loop mapping constrain one another. Optimizing one side alone can produce an unusable design.

↳Choose both the kitchen equipment and the cooking schedule. Two simultaneous frying tasks cannot use one pan at the same time.
02

Make it concrete.

Where can a multiply run?

Interactive · toy example

The toy kernel needs a multiply and an add. An ADD-only array lacks a multiply. Add a MUL-capable unit and the toy operation assignment becomes feasible.

Array [ADD, ADD] cannot directly assign the kernel’s MUL operation. Array [MUL, ADD] supports both required operations. Real mapping also checks routing, timing, and memory; this toy checks operation support only.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Propose jointly

Vary functional-unit allocation and software choices such as loop unrolling.

02

Repair failures

Use tool errors and syntax/mapping repair libraries before ranking candidates.

03

Balance exploration

Shift from diverse proposals toward promising designs, with tool feedback calibrating selection.

The contribution: A four-stage co-design loop with coordinated exploration, repair, selection, and evaluation for CGRAs.

04

Bring the idea to ABCD.

A possible research direction
Workload + CGRA choices→Feasible software mapping→Tool-evaluated feedback

ABCD should preserve the executable mapping and its validation evidence when changing an architecture.

Small experiment: Remove one functional-unit capability and observe whether the system repairs the hardware, changes the mapping, or rejects the proposal.

Keep in mind: MACO is already a close comparison for joint hardware/software search. A different agent organization alone would not demonstrate a new capability.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.

05

Read the result in context.

Three workload domains
8 kernels

Physical-design validation
7 nm flow

The paper reports an ASIC tool flow; this is not a claim of a fabricated test chip.

Scope matters. Power and mapping performance use different tools. Search-efficiency and quality claims depend on the CGRA space, models, and baselines in the May 2026 revision.
