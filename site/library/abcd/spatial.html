Spatial: A Language and Compiler for Application Accelerators

Spatial is a language and compiler that makes accelerator control, memories, and tuning parameters explicit, then generates hardware with optimized pipelines and storage.

01

First, picture the problem.

Turning an algorithm into hardware requires decisions about parallelism, pipelining, and memory access that ordinary software code leaves implicit.

↳Opening four checkout lanes helps only if customers can reach all four.
02

Make it concrete.

Four lanes, how many banks?

Interactive · toy example

Four lanes need four consecutive array elements in one toy cycle. Each bank serves one read. Compare one bank with four cyclically assigned banks.

One single-read bank needs four cycles for four reads. Four banks holding consecutive elements cyclically can serve those reads in one cycle. A different address pattern can still cause bank conflicts.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Expose hardware concepts

Describe nested control, explicit memories, and interfaces.

02

Optimize the implementation

Coordinate pipelining, memory banking, buffering, and parallelism.

03

Tune parameters

Explore legal configurations before generating target hardware.

The contribution: A high-level accelerator language with a compiler and design-space tuning that retain hardware-relevant structure.

04

Bring the idea to ABCD.

A possible research direction
Application algorithm→Control + memory abstractions→Generated accelerator

Use Spatial as a conventional reference when claiming task-to-hardware compilation or automatic design tuning in ABCD.

Small experiment: Vary loop parallelism and bank count together. Check throughput, bank conflicts, and resource use rather than arithmetic-lane count alone.

Keep in mind: The toy assumes conflict-free cyclic banking. Real banking must follow the actual index expressions and memory-port limits.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.
