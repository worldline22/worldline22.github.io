01

First, picture the problem.

A correct accelerator can be useless if its driver, device ID, or system connection is wrong. Component-only tests miss these failures.

↳An engine passing a bench test does not prove the assembled car can drive.
02

Make it concrete.

One mismatched device ID

Interactive · toy example

Our toy driver calls device 7. The accelerator is registered as device 9. Fix the interface and follow the request all the way through.

Driver ID 7 → registered device 9: no matching target, so the application cannot reach the accelerator. Driver ID 7 → registered device 7: the call connects. Matching IDs alone does not prove the returned numbers are correct.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Provide full tasks

Application code and accelerator templates expose both hardware and software design choices.

02

Require integration

Generate accelerator code, driver calls, and the target SoC configuration together.

03

Measure end-to-end

Compare application outputs, CPU-cycle speedup, and FPGA resource use.

The contribution: A benchmark for agent-driven system-level co-design, including failure analysis across hardware, software, and integration.

Follow the idea in the source paper ↗
04

Bring the idea to ABCD.

A possible research direction
Application workload→Integrated accelerators + drivers→Board-level evaluation

Use HSCO-Bench’s integration requirements when defining what counts as a successful ABCD output.

Small experiment: Add a second accelerator to a working application. Check interface consistency, data transfer, correctness, resource fit, and total application time.

Keep in mind: A benchmark identifies and measures a problem; it is not itself a solution to reliable multi-accelerator composition.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.

05

Read the result in context.

Benchmark scope
10 applications

Machine-learning and signal-processing applications on an ESP-based SoC and VC707 FPGA.

Models with successful designs
2 of 5

Only two tested models produced valid SoCs in the evaluation; neither succeeded on every application.

Scope matters. Results depend on the provided platform, agent harness, models, and workload suite. A fast kernel alone does not meet the benchmark’s end-to-end criteria.
