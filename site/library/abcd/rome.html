01

First, picture the problem.

Long RTL generations can lose context and repeat mistakes. Hierarchy offers smaller units to generate, test, and repair.

↳Write and check individual chapters before assembling the book and checking that they agree.
02

Make it concrete.

Repair the faulty leaf

Interactive · toy example

A toy design has a decoder, an ALU, and a register file. Only the ALU fails its local test. Compare rebuilding everything with repairing the leaf.

A whole-design retry revisits decoder, ALU, and register file. A local retry revisits the ALU while preserving the other two definitions. Both routes still need a top-level integration test.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

Assemble and correct

The contribution: Hierarchical prompting modes, an automated generation pipeline, and benchmarks comparing flat and staged generation.

04

Bring the idea to ABCD.

A possible research direction
Module decomposition→Focused generation and repair→Tested integration

Treat stepwise hardware generation as an established reference when designing ABCD’s decomposition workflow.

Small experiment: Inject one error into a three-module design and measure how much code each repair strategy changes.

Keep in mind: In the purely generative mode without submodule tests, the pipeline can select the first submodule candidate. Do not assume every leaf is independently verified.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.
