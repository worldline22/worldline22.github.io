01

First, picture the problem.

An architecture’s efficiency depends on how loops and data are assigned to its processing elements and memory hierarchy.

↳A cook can fetch an ingredient for every serving or keep it nearby while preparing several servings.
02

Make it concrete.

Reuse one weight for four products

Interactive · toy example

Four input values need the same weight. Compare fetching that weight for each multiplication with retaining it locally.

For four multiplications, reloading the shared weight needs four weight fetches. Retaining it needs one initial fetch and four local uses. Arithmetic count stays four. This counts only weight traffic, not every memory access.

Invented teaching example. Values and costs here are not measurements from the paper.

04

Bring the idea to ABCD.

A possible research direction
Architecture + workload→Legal mapping choices→Predicted system costs

Keep ABCD’s target architecture, executable mapping, and performance estimate distinct so each can be inspected and validated.

Small experiment: Hold the architecture fixed and vary only reuse and loop mapping. Compare predicted traffic against an execution trace.

Keep in mind: Timeloop is an evaluation and mapping-exploration tool; a modeled schedule is not automatically a deployed command stream.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.

Nature of the evidence
Analytical

The tool predicts energy and execution costs; modeling assumptions remain part of every estimate.

Scope matters. The performance model assumes properties such as effectively overlapped components and limited pipeline stalls. Real congestion or control overhead can violate those assumptions.
