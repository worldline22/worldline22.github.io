01

First, picture the problem.

On a spatial accelerator, each core has local memory. A fast tile calculation can still stall if cores repeatedly fetch the same data or send it along a congested route.

↳Four cooks need the same recipe. Fetch four copies from the storeroom, or fetch it once and pass it around the kitchen.
02

Make it concrete.

Four cores need the same input tile

Interactive · toy example

Switch how one shared input reaches four cores. Count off-chip fetches separately from on-chip deliveries.

Independent reads: 4 cores fetch the same tile 4 times. Broadcast: fetch it once into core 0, then deliver it to 3 peers. That saves 3 off-chip tile reads, but the on-chip transfers still cost time.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Model the chip

Describe core capabilities, memory sizes, bandwidths, and network topology in a compiler representation.

02

Map and reuse

Assign tile instances to cores and time steps. Plan broadcasts and move repeated loads outside eligible loops.

03

Rank, then measure

An architecture-derived model ranks plans. Optional profiling of top candidates corrects for details the model misses.

The contribution: An end-to-end compiler connecting tile languages to spatial dataflow hardware, with architecture-guided placement, communication, and reuse planning.

04

Bring the idea to Torch-Helion.

A possible research direction
Helion tile program→Hardware-aware dataflow plan→Per-core execution

This is a direct reference for a spatial backend: preserve Helion’s tile computation while adding a separate plan for placement, local storage, and transfers.

Small experiment: Compile one matrix multiply with independent reads and with shared-input broadcast. Compare off-chip traffic, local-memory use, and measured runtime.

Keep in mind: The reuse must be legal, buffers must fit, and broadcasts must match the target network. Reduced traffic alone does not guarantee a speedup.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.

05
