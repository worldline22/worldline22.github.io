01

First, picture the problem.

Adding up isolated kernel runtimes can miss data dependencies, busy links, and memory evictions. These effects change which placement of fused work is best.

↳A delivery kitchen needs an available cook, ingredients on the counter, and a free delivery route. Counting cooking time alone misses the waiting.
02

Make it concrete.

When does the consumer finish?

Interactive · toy example

Core A produces a tile in 2 ticks. Transfer takes 1 tick. Core B consumes it in 2 ticks. Add 4 ticks of link contention and watch the timeline.

Free link: 2 compute + 1 transfer + 2 compute = 5 ticks. Busy link: 2 compute + 4 wait + 1 transfer + 2 compute = 9 ticks. The arithmetic is unchanged; resource availability changes completion time.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Build a fine-grained graph

Split layers into computation tiles and extract the data dependencies between them.

02

Account for resources

COALA models link occupancy, tensor lifetimes, memory capacity, and transfers including eviction and reload.

03

Optimize repeated work

WACO uses constraint optimization on the steady-state portion of layer stacks to choose allocation and scheduling.

The contribution: A design-space exploration framework linking heterogeneous hardware, fine-grained layer fusion, communication-aware analysis, and constrained workload allocation.

04

Bring the idea to Torch-Helion.

A possible research direction
Architecture + tile graph→Memory and transfer timeline→Feasible placement costs

Use a resource-aware cost model when comparing Torch-Helion schedules on a multicore backend. A sum of kernel times will not capture shared-link contention.

Small experiment: Hold compute costs fixed and vary link bandwidth or memory capacity. Check when the preferred core placement changes, then validate the predicted transfers and stalls.

Keep in mind: The browser timeline is a serial toy. Real schedules can overlap computation and communication, share links, and evict tensors.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.
