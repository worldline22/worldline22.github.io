01

First, picture the problem.

A sparse tensor has many zeros. Storing only nonzero values saves work, but the compiler must also track their positions and visit them in a compatible order.

↳Imagine two conveyor belts carrying numbered packages. A worker must match the package numbers before combining their contents.
02

Make it concrete.

A sparse dot product, one match at a time

Interactive · toy example

A = [2, 0, 3, 0] and B = [0, 4, 5, 0]. Only position 2 is nonzero in both. Multiply matching positions, then add the products.

Match coordinates, not positions in the compressed lists: A has (0, 2), (2, 3); B has (1, 4), (2, 5). Only coordinate 2 matches. Result = 3 × 5 = 15.

Invented teaching example. Values and costs here are not measurements from the paper.

03

What did the paper add?

01

Express legal orders

Fused expressions and a partial-order graph retain sparse-format and dependency constraints.

02

Build fusion tables

A planning representation connects coordinate streams, value streams, and computation.

03

Generate the pipeline

Scanners, matchers, arithmetic, and reducers form the streaming program. Factored iteration avoids excess bookkeeping.

The contribution: Cross-expression sparse fusion, enabled by fused expressions with ordering constraints and a fusion-table intermediate representation. This goes beyond combining a single sparse expression.

04

Bring the idea to Torch-Helion.

A possible research direction
Fusion legality→Coordinate + value order→Streaming dataflow plan

For a sparse or dataflow backend, Torch-Helion would need explicit traversal and dependency constraints when connecting operations. A matching shape alone is insufficient.

Small experiment: Try no fusion, partial fusion, and full fusion for a small gather → transform → activation workload. Count intermediate traffic and repeated arithmetic separately.

Keep in mind: Full fusion may repeat work and run slower. The scheduling interface lets users select fusion regions; full automatic schedule selection is future work.

This connection is an interpretation for the project, not an implementation or performance claim by the paper.
